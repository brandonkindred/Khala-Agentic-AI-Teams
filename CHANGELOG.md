# Changelog

All notable changes to this repository are documented here.

## [Unreleased]

### Fixed

- **Investment / Strategy Lab — per-trade loss and position size are one quantity; `max_loss_per_trade_pct` removed.** The deployed position size *is* the most a single trade can lose (an entered position can lose up to ~100% of what it deploys), so the per-trade loss cap and the position-size cap were duplicate values expected to be equal. They are now consolidated onto `max_position_pct` (the clearer name) and `max_loss_per_trade_pct` is removed from `RiskLimits` (`backend/agents/investment_team/execution/risk_filter.py`); `from_legacy_dict` drops the retired key and the authored `max_position_pct` stands — the two are NOT folded together, because under the old model `max_loss_per_trade_pct` was a different quantity (a stop-governed realised-loss tolerance, `fraction × stop`), so importing it as a deployed-capital cap would wrongly shrink the position (e.g. `{max_position_pct: 10, max_loss_per_trade_pct: 0.5}` from a 10%-deployed × 5%-stop spec would collapse to a 0.5% cap, a 20× reduction), and a legacy `0`/negative/`None` value would silently zero or fail to validate the cap. This retires the readiness gate's Rule 9 "Check B" — the `risk_limits:loss_tolerance`, `risk_limits:loss_tolerance_no_stop`, `risk_limits:zero_loss_tolerance`, and `risk_limits:custom_code_unenforceable` criticals — leaving the deployed-cap check (`sizing:position_cap`) plus the prose-deployment warning; and removes the redundant runtime `_cap_qty_to_loss` clamp (the position clamp already enforces `max_position_pct`). `stop_loss.pct` is now correctly modeled as an independent, optional within-position safeguard — a price move off entry, never multiplied into the cap. A SHORT can lose more than 100% of deployed capital (price can more than double), so `TradingService` now auto-injects a 100%-adverse-move stop (`StopLossRule(pct=1.0, basis="entry_price")`) for any short that lacks an effective stop, bounding a short's modeled worst-case loss at the deployed size too. Design prompts (`design_system`, `design_review_system`, `design_self_review_system`) were corrected to teach the deployed-cap model. Tests: `tests/{test_spec_readiness,test_engine_entry_dispatch,test_trading_service,test_engine_exit_enforcement,test_orchestrator_helpers,test_audit_recent_runs}.py`.
- **Investment / Strategy Lab — crypto `-USD` canonicalization hardened against compound and empty suffixes.** `canonical_symbol(symbol, asset_class)` (`backend/agents/investment_team/symbols.py`) stripped only a *single* trailing `-USD` via an `if`, with no guard against an all-suffix input. A compound-suffixed crypto ticker (`DOGE-USD-USD`) therefore collapsed to `DOGE-USD`, missed the `YAHOO_CRYPTO_TICKERS` lookup, and was re-suffixed by the Yahoo fallback back into the malformed `DOGE-USD-USD` — the exact double-suffix the centralized normalization was meant to eliminate, just one cycle later; a literal `-USD` collapsed to an empty alias that was rebuilt into `-USD` and sent verbatim to yfinance. The helper now strips *every* trailing `-USD` with a `while` loop (`DOGE-USD-USD → DOGE`) and raises `ValueError` when a crypto symbol collapses to empty (`-USD`, `-USD-USD`), treating it as the invalid input it is rather than forwarding a malformed bare ticker to a provider or the cache. Because every provider path and the content-hashed market-data cache route through this single helper, the fix covers Yahoo, Twelve Data, Alpha Vantage, and CoinGecko at once. Tests: `tests/test_market_data_service.py` (compound-suffix + empty-raise unit cases, plus Yahoo and CoinGecko provider-level regressions).
- **Investment / Strategy Lab — indicator functions accept `list[Bar]` / `list[float]`, not only `pd.Series`.** Strategy sandbox runs were consistently failing with `'list' object has no attribute 'ewm'` (mis-reported as `error_type=lookahead_violation`) because the code-synthesis prompt documents `ctx.history(symbol, n) -> list[Bar]` while the shared indicator helpers silently required `pd.Series`. When generated strategy code passed the history list straight into `ema(history, period)`, the `.ewm`/`.rolling` call blew up on a plain `list`. The fix coerces at the single boundary we control: a new `_coerce_series(series, field="close")` helper in `strategy_lab/executor/indicators.py` accepts `pd.Series` (pass-through), `list[float]`, `list[Bar]`/OHLCV objects (extracts the field), and `list[dict]`, and every public indicator (`sma`, `ema`, `rsi`, `macd`, `bollinger_bands`, plus the multi-series `atr`, `adx`, `stochastic`, `vwap` with per-argument field extraction) now coerces its inputs up front. Bad input raises a clear `TypeError` (never `AttributeError`). The streaming harness (`trading_service/strategy/streaming_harness.py`) no longer mislabels an indicator-module `AttributeError` as `lookahead_violation` — it classifies traceback frames originating in `indicators.py` as `runtime_error`. The synthesis prompt now documents that indicators accept the `list[Bar]` from `ctx.history` directly. The coercion also accepts an object-dtype `pd.Series` (preserving its index), generic non-string sequences (`collections.deque`, `np.ndarray`), and validates every element (rejecting `bool` anywhere and normalising malformed-element failures to `TypeError`). Separately, the indicator return-type contract is now consistent across both execution paths: a new scalar-returning `strategy_lab/executor/strategy_indicators.py` (latest value per indicator; tuples for `macd`/`bollinger_bands`/`stochastic`) is the single source of truth shared by the streaming sandbox (copied in as `indicators.py`, with the Series implementation alongside as `_indicators_impl.py`) and the predicate-conformance shadow gate — previously the sandbox exposed the Series-returning module while the gate returned scalars, so a strategy using `if ema(history, 20) > bar.close` worked in one path and raised pandas' ambiguous-truth error in the other. The Series-returning `executor/indicators.py` remains the engine-internal implementation (predicate evaluator, rule probes). Tests: `tests/test_executor_indicators.py` (coercion paths, index preservation, deque/ndarray, bool/malformed rejection) and new `tests/test_strategy_indicators.py` (scalar contract, multi-series, flat-sandbox import layout); verified end-to-end through `StreamingHarness`.

### Added

- **Agent Cognition — invoke gate: run-once idempotency, durable rule blocks, and writeback persistence at the invoke boundary.** The inject-on-invoke / writeback-on-return contract is now live (Agent Cognition `IMPLEMENTATION_PLAN.md` Step 10). New `backend/agents/agent_cognition/invoke_gate.py` is the reusable lifecycle orchestrator over the `context.py` facade, consumed by `POST /api/agents/{id}/invoke` (`unified_api/routes/agents.py`) and by in-process callers via `invoke_in_process(agent_id, body, runner)` (no HTTP hop, identical contract). Per invoke: a stable `source_run_id` is derived (caller `Idempotency-Key` header, else the SHA-256 of the body's canonical JSON, so byte-identical keyless retries still dedup) and claimed in the leased `agent_cognition_runs` ledger — a terminal row with a matching hash **replays the stored envelope without re-invoking** (covers `blocked` rows, so a retried rule block replays the same 4xx; replays carry `X-Khala-Replayed: true` and skip sandbox + console-row writes), a hash mismatch or still-valid lease is `409`, an expired lease reclaims in place and re-executes. Manifests with `cognition.requires_idempotency_key: true` reject keyless invokes `400`; when the ledger is unreachable such agents fail closed `503` while other cognition agents degrade to an unledgered invoke (a cognition outage never breaks the invoke). The gate also adds lazy rollup catch-up before context load, persists a memory event + the `blocked` ledger envelope on an enforced precondition block, re-applies `AGENT_INVOKE_MAX_PAYLOAD_BYTES` to the **full** marker-wrapped envelope (413 — the side channel shares the payload budget), and runs the enforced postcondition **before** any persistence — fixing the prior ordering where the console run row stored the model output before the gate evaluated it. On violation the model output and agent-authored memory are dropped everywhere while the shim's trusted `tool_audit` is persisted (as `tool_call` events) plus a blocked-run event; on success the envelope's `memory_events` are validated defensively (malformed entries dropped with a warning) and persisted, and the ledger row completes with `{status_code, content}` for replay (stored without the per-invoke `sandbox` block so a replay can't masquerade as a fresh boot). Upstream shim failures persist only the trusted audit and leave the lease to expire so a retry re-executes. The warming `202` path deliberately precedes the gate — claiming a leased run and then answering "retry shortly" would make every warm-up poll conflict with its own claim. Proxy-side `platform_bound` tool-loop driving remains gated on the generated-agent runtime scaffold (`drive_platform_bound_loop` landed with the tools layer). Post-review hardening: **attempt-scoped memory keys** — events persist under `{source_run_id}#{attempt_token}` so an expired-lease re-execution's new side-effect events can never silently dedup against a failed attempt's rows; **structured Pydantic outputs in `invoke_in_process`** — a runner returning a `BaseModel` is dumped to a dict (not stringified), keeping the postcondition gate and stored replay envelope structured; **claim release** — new `context.abandon_run` (claim-token-fenced DELETE) frees the claim on paths where the agent provably produced nothing to protect (oversize wrapped envelope 413, over-cap upstream response 502), so immediate retries re-execute instead of 409-ing until lease expiry, while transport errors deliberately hold the lease as the double-run guard; **budgeted lazy catch-up** — `ensure_rollups_current` gains `max_periods` (+ `RollupReport.truncated`) and the gate passes `AGENT_COGNITION_INVOKE_ROLLUP_BUDGET` (default `8`, each period ≈ one LLM call) so a cold-start backlog can't run hundreds of sequential LLM calls inline; **fail-closed postconditions** — a 2xx response without an object `output` on an agent carrying enforced postcondition rules now blocks (rules evaluate against `{}`) instead of silently skipping the gate; **one status map** — `GATE_ERROR_HTTP_STATUS` is exported and shared by the HTTP route and the in-process helper; blocked outcomes carry structured `block_phase`/`block_reason` so callers never parse the stored HTTP body; the shared `FakeRunLedger` test double moved to `agent_cognition/testing.py`. A second review pass tightened the seams further: the fail-closed non-mapping-output coercion moved **into** `context.enforce_postcondition` itself so direct callers get identical semantics; the route now fails loudly (`500`) on a gate outcome kind it does not recognize instead of silently proceeding ungated; the attempt-scoped `source_run_id` format is documented at the store contract (`persist_writeback` / `MemoryEvent` — correlate events to ledger rows by splitting on the **last** `#`, since caller keys may contain `#` but attempt tokens are UUIDs); `_record_block` builds the blocked envelope exactly once and returns it (stored replay body and live response can never disagree); and the hot path sheds redundant work — the proxy posts the gate's already-serialized envelope bytes, the ledger stores the parsed response without a defensive re-serialization round-trip (the proxy now adds its `sandbox` block on a copy, never mutating the stored envelope), and event persistence + ledger completion run concurrently. ### Changed

- **Shared background-heartbeat driver (`shared_concurrency.BackgroundHeartbeat`) replaces seven hand-rolled copies.** The "daemon thread runs a callable on an interval until stopped" scaffolding — a `threading.Event` stop flag, a daemon thread looping on `event.wait(interval)`, best-effort beat, and a `finally` that stops + joins — had drifted across seven independent copies: the SE Temporal coding-team activity keep-alive (`software_engineering_team/temporal/activities.py`), the founder spec-generation heartbeat (`user_agent_founder/orchestrator.py`), the SE job-store heartbeat thread (`software_engineering_team/shared/job_store.py`), the SE team's stale-job monitor (`software_engineering_team/api/main.py`), the blogging pipeline heartbeat (`blogging/shared/run_pipeline_job.py`), the blogging event-bus reaper (`blogging/shared/job_event_bus.py`), and the job-service stale-job monitor (`job_service_client.py`). All seven now delegate to one generic driver, `backend/agents/shared_concurrency/heartbeat.py`, parametrized on the axes they differed on: stop semantics (external `stop()` / context-manager exit, an injected caller-held `stop_event`, **or** a self-terminating `should_continue` predicate), beat timing (wait-then-beat or `beat_first` for an immediate first run, e.g. the stale-job sweep on startup), error policy (silent swallow **or** an `on_error` hook), optional `contextvars` capture (the beat **and** the predicate run in the same captured context — no asymmetry), and `join_timeout`; `is_alive()` reports thread state. A raising beat or predicate is routed to `on_error` and never kills the loop. The driver lives in the new **`shared_concurrency`** package (not `shared_temporal`) because it is Temporal-agnostic and several callers (the stale monitor, the reaper) are not Temporal users; importing it pulls in only the stdlib. Additionally, the coding-team activity's **ambiguous double-heartbeat is resolved**: the background beater is now the single liveness owner, and the orchestrator update callback (`_coding_update_callback`, formerly `_heartbeat_update_callback`) only persists progress — it no longer also calls `activity.heartbeat()`. Public signatures of `start_job_heartbeat_thread`, `_generate_spec_with_heartbeat`, and `start_stale_job_monitor` (still returns its caller-held stop `Event`) are unchanged. Tests: new `shared_concurrency/tests/test_heartbeat.py` (100% line coverage on the driver — beats-until-stopped, prompt join, swallow-vs-`on_error`, self-terminate, predicate-error survival, beat+predicate context capture, `beat_first`, injected `stop_event`, `is_alive`, idempotent start, context-manager, precondition rejection); existing heartbeat/reaper/pipeline tests across the SE, founder, and blogging suites continue to pass, with the activity tests updated to assert the update callback no longer heartbeats.
- **`llm_service.strands_adapter.LLMClientModel.config` is now an independent dict view per access (potentially breaking for external callers).** As part of the PR #517 / #582 cleanup, the model's internal config moved from a mutable `Dict[str, Any]` to a frozen `LLMClientConfig` dataclass. `LLMClientModel.config` is kept as a property (Strands' `Agent` loop calls `model.config.get(...)` internally and the contract must be preserved) but it now returns a **fresh** `dataclasses.asdict(...)` snapshot on every access — mutations on the returned dict no longer persist to the model. ### Fixed

- **Coding team UI: "Confirm & Start" on a GitHub issue no longer fails with an opaque `0 Unknown Error`.** The unified API image now installs `git` (the GitHub issue-to-PR route shells out to it to clone/fetch the target repo), the shared team-service image installs `git` for the coding team's branch/commit/push during code-generation jobs, and `POST /api/integrations/github/run-issue` now converts clone/timeout/connection failures into explicit `502`/`503`/`504` responses instead of unhandled `500`s — those were emitted outside the CORS middleware, so the browser dropped the response and the UI could only surface a status-0 error. `_ensure_repo_clone` no longer lets `subprocess` errors escape and scrubs the token from `git fetch` stderr. The coding-team service now also threads the GitHub credential through its own network git operations (`_prepare_issue_branch` fetch and `_push_branch` push) using the same transient `GIT_CONFIG_*` Bearer-header pattern as the clone — the token is never persisted to `.git/config`, which matters because the checkout lives on the shared `agents_data` volume; without it a default checkout had no credentials and the background job would fail at push (or hang until the git timeout) after `/run-issue` already returned success. Code: `backend/Dockerfile`, `backend/team_service/Dockerfile`, `backend/unified_api/routes/integrations.py`, `backend/agents/coding_team/api/main.py`. Tests: `backend/unified_api/tests/test_integrations_github_route.py` (19 cases), `backend/agents/coding_team/tests/test_github_source.py` (credential-threading cases).
- **Investment / Strategy Lab — non-finite-OHLC defense now applied across every market-data provider, and Rule 5 no longer drops the price defense for fractional asset classes.** Two related data-integrity gaps where a safeguard existed on one path but not its siblings. (1) The non-finite-OHLC row filter lived only in the yfinance helper (`_df_to_bars`); the Twelve Data and Alpha Vantage ingest loops built bars with `round(float(...))` and no finiteness check, so when Yahoo cascaded to a fallback whose response carried a NaN (or a string `"nan"`), the row became an `OHLCVBar` with NaN fields and tripped the downstream sizing-realisability gate with "got nan" — intermittently, depending on which fallback the chain landed on. The round/finite-check/H-L-envelope-repair logic is now centralized in a shared `MarketDataService._normalize_ohlc_bar(...)` helper used by all four provider paths (yfinance, Twelve Data, Alpha Vantage, and CoinGecko, whose aggregated price list could likewise surface a NaN through `max()/min()`); each path drops non-finite rows identically and logs the dropped count. (2) `SpecReadinessGate._check_sizing_realisability` short-circuited the per-symbol price loop for fractional classes (forex/crypto), discarding the only NaN/zero/negative-price defense; a persistently broken provider (a `0.0` parsed from a rate-limit body, a negative sentinel, or persistent NaN) was silently ignored. The loop now runs for every asset class: a finite non-positive price is a broken-provider critical regardless of class; a non-finite price stays a hard critical for whole-lot classes but, for fractional classes, is tolerated when any symbol still resolves to a finite price (transient weekend/holiday gap) and downgraded to a non-blocking warning only when it affects every symbol. Code: `backend/agents/investment_team/market_data_service.py`, `backend/agents/investment_team/strategy_lab/quality_gates/spec_readiness.py`. Tests: `tests/test_market_data_service.py`, `tests/test_spec_readiness.py`. (Provider `float(None)`/`float(pd.NA)` TypeError-safety is tracked separately and intentionally out of scope.)
- **Investment / Strategy Lab — crypto `-USD` symbol normalization centralized across all market-data providers and the cache.** Previously only the Yahoo and CoinGecko fetch paths stripped a trailing `-USD` from crypto tickers, so a spec using `target_symbols=['BTC-USD']` that fell through to the Twelve Data or Alpha Vantage fallback produced a malformed `BTC-USD/USD` (Twelve Data) or a not-found bare `BTC-USD` (Alpha Vantage), surfacing as a generic "symbol unavailable" instead of correct data. Normalization now happens once in a shared `canonical_symbol(symbol, asset_class)` helper (`backend/agents/investment_team/symbols.py`): `MarketDataService._fetch_with_providers` collapses crypto tickers to their bare alias before the provider chain, so all four providers receive the same canonical input and re-suffix it to their own convention. The same helper runs at the `fetch_ohlcv_range` / `fetch_multi_symbol_range` entry points to key the content-hashed market-data cache, so the bare alias and the Yahoo-suffixed form of a coin (`BTC` / `BTC-USD`) now share a single snapshot and fingerprint instead of being cached as two distinct datasets; the result dict and `provider_used` are re-keyed back to each caller's original symbol so downstream provenance and target-coverage logic are unaffected. Code: `backend/agents/investment_team/{symbols,market_data_service}.py`. Tests: `tests/test_market_data_service.py`, `tests/test_market_data_extras2.py`.
- **`user_agent_founder` spec generation:** the "Startup Founder Testing Persona" run no longer fails with `LLMJsonParseError` when the model returns Markdown. `FounderAgent.generate_spec` now bypasses the Strands / `chat_json_round` JSON-only transport and calls `LLMClient.complete` directly via a new `_call_text` helper. `FounderAgent.answer_question` migrated to `generate_structured` with a `FounderAnswer` Pydantic schema (canary for the new API); the bespoke regex/`json.loads` fallback was removed in favor of the self-correction guard.
- **Ollama structured JSON:** responses with unescaped double quotes inside string values (common when the model cites snippets like `"Resource": "*"`) are parsed using a **`json-repair`** fallback in `OllamaLLMClient._extract_json`. Blog copy-editor prompt updated to require escaped or single-quoted inner quotes.
